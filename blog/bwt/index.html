Introduction

This series of interactive articles tries to take commonly used genomic and transcriptomic bioinformatic tools and explain their underlying mechanisms. In this article, we will explore the seemingly magical algorithm of Burrows-Wheeler Transform (BWT), also known as block-sorting compression. BWT is not particularly intuitive to the human processing, especially with repetitive genomic sequences but can reach O(n) time with optimal algorithms.

Burrows-Wheeler transform has two main purposes and you have likely encountered them: 1. Pre-processing step to data compression: The BWT serves as the foundation for a number of lossless data compression algorithms (you may have heard of bzip or bzip2), some of which are employed for maintaining massive amounts of genetic sequencing data. 2. Short-read mapping: Several modern short-read aligners, including bowtie, bwa, and soap2, efficiently build an index of a given reference genome using algorithms based on the BWT.

Below are some helper functions used for the calculations in this tutorial.

Code 
function cleanInput(s) {
  s = s.replaceAll(" ", "")
  s = s.replaceAll("$", "")
  s = s + "$"
  return s
}

function getRotations(s) {
  const n = s.length;
  return Array.from({length: n}, (_, k) =>
    Array.from({length: n}, (_, i) => s[(i + k) % n]).join("")
  );
}

function getSortedRotations(s) {
  return getRotations(s).sort();
}

function computeBWT(s) {
  return getSortedRotations(s)
    .map(r => r[r.length - 1])
    .join("");
}

function buildTable(rotations, n) {
  const tbody = document.createElement("tbody")

  rotations.forEach((rotation) => {   // ← "sorted" becomes "rotations"
    const tr = document.createElement("tr")
    
    rotation.split("").forEach((char, colIndex) => {
      const td = document.createElement("td")
      td.textContent = char

      td.style.cssText = `
        padding: 6px 18px;
        font-family: monospace;
        font-size: 1.1em;
        text-align: center;
      `

      // $ highlighting
      if (char === "$") {
        td.style.color = "#0369a1"
        td.style.fontWeight = "bold"
      }

      // First column → blue
      if (colIndex === 0) {
        td.style.backgroundColor = "#e0f2fe"
        td.style.fontWeight = "bold"
        td.style.color = "#0369a1"
      }

      // Last column → indigo
      if (colIndex === n - 1) {
        td.style.backgroundColor = "#4f46e5"
        td.style.color = "white"
        td.style.fontWeight = "bold"
      }

      tr.appendChild(td)
    })

    tbody.appendChild(tr)
  })

  const table = document.createElement("table")
  table.style.cssText = `
    border-collapse: collapse;
    margin-top: 0.5rem;
  `
  table.appendChild(tbody)

  return table
}

function inverseBWTSteps(bwt) {
  const n = bwt.length
  let matrix = bwt.split("").sort()
  
  const steps = [matrix]  // step 0: just sorted single chars
  
  for (let i = 0; i < n - 1; i++) {
    matrix = matrix.map((row, j) => bwt[j] + row)
    matrix = matrix.sort()
    steps.push(matrix)    // ✅ save each step
  }
  
  return steps
}

The Rotation Matrix

First, let’s look at the data compression step. In essence, the BWT manipulates a block of input text using a reversible transformation, this in itself, does not compress the text but reorders it (permutes) in a way that facilitates compression. Let’s first take a look at the rotation matrix below, currently showing the classic example “banana”, but feel free to change this to investigate how different strings are organized.

To find the BWT, we can first build the Burrows-Wheeler Matrix (BWM) which is a sorted list of all possible rotations of the given string.

What is the $ Symbol

The $ symbol is indicating the end of the string and is necessary to make the BWT fully reversible. Without the $ marker, you can still regenerate the matrix, but you wouldn’t be able to tell which rotation was the original format. All of these issues become amplified when looking at large genomic data.

Compression

How does this help with compression if the length of the BWT is the same as the length of the original string? To put it frankly: BWT alone cannot compress a string. Instead, it rearranges the data so that similar symbols are clustered together, making the output more amenable to compression. Burrows and Wheeler published the BWT in 1994 as part of the Block-sorting Lossless Data Compression Algorithm, or BSLDCA. Modern compressors, such as bzip2, follow essentially the same pipeline: BWT, move-to-front coding, and run-length encoding, and Huffman coding. These are commonly employed for maintaining massive amounts of genetic sequencing data .

It was invented by David Wheeler in 1983, and later published by him and Michael Burrows in 1994. Their paper included a compression algorithm, called the Block-sorting Lossless Data Compression Algorithm or BSLDCA, that compresses data by using the BWT followed by move-to-front coding and Huffman coding or arithmetic coding.[1][2]

Reversibility

Of course, any sorting algorithm can make a string easily more compressible. e.g. If we just lexographically sort banana -> aaabnn -> character frequency list. But the beauty of BWT is that the compressed string can be reversed into the original string.

The logic in reversing BWT using the BWM follows that the BWT is the sorted version of each previous one (fix whatever this explanation is). Therefore, given the encoded string, we can reconstruct the matrix by starting wtih an empty matrix, then with each step, prepending the BWT string, sorting the strings, and repeating until the matrix is filled. Move the slider to see each step.

      ${step === n-1 ? html`<p>✅ Original string: <strong>${currentMatrix.find(row => row.slice(-1) === "$")}</strong></p>` : ""}

Suffix Arrays

Our current method of generating the BWT is currently very inefficient, requiring each rotation for len(s). Using suffix arrays, we can change this from O(nlogn) tiem to linear time using a more efficient method. Each suffix is just a part of a word at a different index. Short-read Mapping

Now you have a good grasp on what BWT is, how to generate and ungenerate it. But how does this help with short-read mapping? Well here’s where we get into the fun properties that come BWT and perform Last-to-First Mapping (LF Mapping).

LF mapping can help us find a substring within the larger string using the property that the first column is just the last column in sorted order. And with this property, the character in the first column is just the character that comes after the character in the last column. F is the character that immediately follows L. L in the original string S becuase each row is a cyclic rotation.
